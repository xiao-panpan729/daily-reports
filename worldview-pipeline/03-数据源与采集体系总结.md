三个坑，未来任何人接手必读：

## 十、2026-09-15 数据可信度加固（换源 · 自检 · 归档）

起因：用户发现日报 `VIX=15.84` / `WTI=97.26` 与市场实际不符。三源交叉验证（FRED / Yahoo / 新浪）后确认
**用户全对**，而且根因分两类，此前一直没暴露。

### 10.1 两类根因

**A 类 · 源本身滞后，代码不知道**：`_fred_latest()` 只取"最新一个非空观测"，
**不记录也不判断这条观测属于哪一天** → 滞后的值静默流入，还配上一个看起来完全正常的涨跌幅。

| 指标 | 日报原值 | 真实值 | 滞后 |
|---|---|---|---|
| VIX | 15.84（实为 09-11 收盘） | **17.10** | 1 个交易日 |
| WTI | 97.26（实为 09-09） | **102.75** | **4 个交易日**（DCOILWTICO 是 EIA **现货**，非期货） |

**B 类 · 源是死的，代码不知道**：Hyperliquid 零成交永续，价格永远不动（markPx 恒等于初始占位值），
代码照样当真值用。全 universe 120 个标的里 **16 个是零成交死标的**，其中 `xyz:VIX`、`xyz:DXY`
恰好被放进了焦点表 —— 日报里那条派生信号 `VIX 永续−现货差 = 4.16` 就是这么算出来的（假数减真数）。

> **为什么一直没暴露**：日报脚注写着"非更新日变动显示 +0.00%（源未出新值，非真的没动）"——
> 这句话把"数据滞后"合理化成了正常现象，连续 4 天 WTI 都是 +0.00% 也没人警觉。

### 10.3 VIX 期限结构（回答"不是还要和期货对比吗"）


### 10.4 新增自检层 `verify.py`（零 token）

| 检查 | 内容 |
|---|---|
| ① 内部一致性 | 同一指标在报告各节必须同值，且等于快照权威值（这条当场抓到 VIX 一节 15.84／另一节 17.10） |
| ② 双源比对 | VIX/WTI/DXY/黄金 对独立第二源（新浪/东财），偏差 >2% 报警 |
| ③ 数据时效 | `asof.json` 里的日频指标超 4 天即列 |
| ④ **数据日新鲜度** | 第二源取数时带自己的时间戳；**「第二源已进新交易日」+「值明显偏离」同时成立**才判我方滞后。单看值会把盘中时差误判成错误；单看日期会在跨日但值未变时白警 |
| 门控 | 无异常 → **不生成** `verify_todo.md` → bat 不叫 CLI（省 token）；有异常才触发 CLI 上网核验 |

`--self-test` 是回归断言（喂人造错值必须被检出、正确值必须零误报、两个值必须抓到节间矛盾、
WTI 事故必须复现、跨日值没变不许白警、盘中偏离不算错），**6/6 通过**才算检查器可信——
只跑真实数据"没报错"说明不了任何事，也可能是它根本没在工作。

> 第二源失效已纳入告警：某个源连续取不到数会写进 `verify_todo.md`，由 CLI 去找替代端点。

### 10.4b CLI 自动改码的护栏（2026-09-15 放权后增）

源失效时，CLI 不再只是"报告替代端点"，而是**被授权直接改 `.py`**。但它改的是下一轮还要跑的代码，
所以 `[6/9]` 的异常分支加了留底 + 三道校验 + 自动回滚：

| 环节 | 命令 | 作用 |
|---|---|---|
| 留底 | `verify.py --snapshot` | 备份全部 `.py` + 记 sha256 + 记**改前异常数** |
| 授权 | CLI `--allowedTools` 含 `Edit` | 提示词限定：只改端点/字段/**解析**，不动阈值、判定规则、函数签名 |
| 校验① | `py_compile` | 拦住缩进/括号这类硬错误 |
| 校验② | 子进程 `import <模块>` | 拦住模块级 NameError、坏 import |
| 校验③ | 子进程重跑 `verify.py` | 拦住「改了但更差」——**异常数不得增加** |
| 回滚 | 副本覆盖 + 删新增文件 + 再跑一次自检 | 最坏退化成"没改"，而不是"管线断掉" |
| 汇报 | 日报末尾「### 5. 本次自动修复」 | 结论（已生效/已回滚）／改动文件／**旧端点 → 新端点**／校验结果表 |

两个防误伤设计：**快照超 120 分钟就拒绝校验**（避免把期间的人工改动当 CLI 改动回滚）；
**只比对 `(日期, key)` 之外的脚本文件**，`_` 开头的临时补丁脚本不纳入。

三道校验全绿才改码生效；实测五个分支：良性改动保留 / 语法错回滚 / 效果变差回滚 /
新增坏文件回滚并删除 / 无改动跳过。

### 10.6 归档步的 push 自愈（2026-09-15）

云端 Actions 也在往同一个 main 推 whale 快照（约每 6 小时一次），撞上时 `git push` 会被拒。
bat `[8/9]` 步现在自动 `git fetch origin main` + `git merge --no-edit FETCH_HEAD` + 重推一次。

- **`--no-edit` 不能删** —— 删了 git 会打开编辑器，bat 会永久卡死在那一步
- 用 `FETCH_HEAD` 而非 `origin/main` —— 本机 git 的远端跟踪引用写不进磁盘（老坑）
- 真冲突 → `git merge --abort` 后打印 warn 交人工，不留半截合并状态
- 用本地 bare 仓库 + 双 clone 完整实测过三条分支：被拒重推成功 / 无改动不空提交 / 冲突安全中止
