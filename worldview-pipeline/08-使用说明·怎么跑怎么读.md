# 08 · 使用说明 · 怎么跑、怎么看、怎么喂 AI

> 2026-09-08 建立，2026-09-15 更新（第 [6/9] 步数据自检 + 每日归档 + push 自愈）。世界观宏观层（world_feed v3 + macro_insight）的日常操作手册。

## 一、平时怎么跑（两条路）

**自动路（推荐）**：双击 `世界观采集.bat`，一条龙跑完 9 步（含同步、自检、发布）：
```
[0/9] git sync (fetch + fast-forward)        采集前先同步远端（用 FETCH_HEAD，见下"坑"）
[1/9] world_feed.py      采集（HL 全量标的 + Polymarket + FRED 15序列 + Yahoo + 中债/货币网）
[2/9] social_feed.py     ApeWisdom 讨论度
[3/9] whale_link.py      拉 A 线云端鲸鱼快照（只 fetch，不动工作树）
[4/9] macro_insight.py   宏观逻辑链引擎（判级 + 异动 + AI 简报）
[5/9] report.py          生成 worldview_daily.md
[6/9] verify.py          数据自检（零 token）+ 归档 daily.csv；有异常才叫 CLI 上网核验（并可自动改码换源）
[7/9] codebuddy CLI      出晨报（带联网研究层）
[8/9] git commit + push  归档快照（被拒会自动同步重推一次，见下"坑"）
[9/9] 发布晨报到站点     publish_site.py → daily-reports（GitHub Pages）
```
平时只跑这一下就够。**建议时机：早上 8:30 后**（FRED/统计局多在美东收盘后+北京时间早上更新）。

> **[6/9] 数据自检是干什么的**（2026-09-15 新增）：
> 本地零成本检查四件事——① 同一份报告里同一指标有没有出现两个值 ② 我方值 vs 独立第二源（新浪/东财）
> ③ 日频数据有没有超期 ④ **数据日是不是最新的**（第二源已进新交易日 + 我方还是旧值 = 我方滞后）。
> **没异常就完全不叫 LLM**（省 token）；有异常才写 `data/verify_todo.md` 触发 CLI 上网核验，
> 结论并入日报末尾「附：数据自检」。检查结果同时归档进 `data/daily.csv`（只装通过自检的值）。
>
> **[6/9] 的 CLI 现在可以自己改代码换源**（2026-09-15 放权）：源挂了、CLI 找到替代端点后，
> 它被授权**直接改 `.py` 里的 URL/字段**，不用等你人工落码。改完自动过三道闸门：
> 语法（`py_compile`）→ 导入（`import`）→ 效果（重跑自检，异常数不得增加）。
> 任一关不过就用 `--snapshot` 留的副本**自动回滚**，最坏退化成"没改"，不会让管线断掉。
> 它动了什么、校验结果如何，固定汇报在日报末尾「### 5. 本次自动修复」（含旧端点 → 新端点）。
> 只在"只改端点、不动阈值/判定逻辑"的范围内被允许——这条靠提示词约束，所以每天留意一下那段汇报。

> **[0/9] 为什么用 FETCH_HEAD**：本机（公司机）git 的远端跟踪引用 `origin/main` **写不进磁盘**
> （fetch 报成功但 `refs/remotes/origin/main` 不存在 → `merge origin/main` 直接 "not something we can merge"）。
> 所以同步步写成 `git fetch origin main` + `git merge --ff-only FETCH_HEAD`，两种环境下都能工作。

> **[8/9] push 被拒会自动重试一次**（2026-09-15 新增）：云端 Actions 也在往同一个 main 推 whale 快照
> （约每 6 小时一次），万一你的 push 撞上它被拒，bat 会自动 `fetch` + `merge` + 重推，**你无感**。
> 只有真冲突（同一个文件双方都改）才会停下并打印 `[warn] merge conflict - aborted`，等你人工处理。
> ⚠️ 内部用 `git merge --no-edit FETCH_HEAD`，`--no-edit` 不能删——删了 git 会打开编辑器，bat 会永久卡死。

> **[9/9] 晨报自动上站**：跑完自动把当天晨报发到站点，无需手动操作。
> 发布器 = `publish_site.py`（本目录），站点 = `D:\daily-reports`（与 `D:\Worldview` 同级）。
> 站点首页会多出一节「世界观晨报（B线）」，线上地址 https://xiao-panpan729.github.io/daily-reports/
> 找不到发布器/站点时**只 warn 不阻断采集**；内容没变时不会产生多余提交（幂等）。

**手动补跑**（改了代码或想刷新某块时）：

## 二、生成的报告怎么看（谁看哪份）

| 文件 | 给谁 | 看什么 |
|---|---|---|
| `worldview_daily.md` | **人** | 今日态势一句话 → 焦点涨跌表 → 宏观读数（中文名）→ 逻辑链判级表 + 派生信号 |
| `data/ai_daily.md` | **AI**（整段粘给 Claude/ima） | 判级变化 diff → 异动榜 → 今日完整状态 → 最近7天记忆 + 输出任务指令 |
| `data/llm_brief.md` | **AI**（要深度推演时） | 全部数字带日期口径 + 五+一条链逻辑 + 开放式推演任务 |
| `data/chains.json` | 程序 | 机器可读全量状态 |
| `data/ai_memory.jsonl` | 程序 | 逐日状态滚动记忆（AI 不丢环境的底座，自动追加，别手改） |
| `data/daily.csv` | 程序 + 人 | **每日归档**：只装**通过自检**的值，主键 `(数据日, key)`，读-改-写幂等，可直接当时间序列用 |
| `data/verify_log.jsonl` | 程序 | 每次自检追加一条 → 能回溯"哪天数据出过问题" |
| `data/verify_report.md` | 人 | 自检报告全文（日报末尾「附：数据自检」的来源） |
| `data/asof.json` | 程序 | 每个值的「数据日 + 来源」留痕，日报的「数据日」列读它 |

**三条读数据的纪律**（2026-09-15 加）：

1. **看「数据日」列，不只看数值。** 日报里每个值都标了它属于哪一天；标 ⚠️ 的就是滞后项，不是今天的数，别当今天读。
2. **日报末尾的自检节必看。** 它直接告诉你"这次的数据有没有问题"，`全部通过` 才值得信。
3. **`daily.csv` 是唯一"确认过"的序列。** 没通过自检的值不会进它——哪天缺了，说明那天数据有问题（`verify_log.jsonl` 里有原因）。

**日报里的判级图标**：🔴 危险 / 🟡 偏高或分化 / 🟢 正常 / ⚪ 数据不足。每条链的逻辑与阈值写死在 `macro_insight.py`，不是拍脑袋。

**数据透明铁律**：每个数字都带"数据日期"。看到"金十源停更仅参考""同比自算"这类标注，说明口径特殊——不是最新数据装新，也不是旧数据冒充。

## 三、给 AI 消费的正确姿势（回答"向量数据库？"）

你记的那个是**「假设卡片」**（03 文档 §六：等数据积累几周后对四条链做 w 权重校准"数据对答案"）。它不需要向量库——每天延续解读的正确工具是**滚动状态文件**（TradingAgents decision memory 同款思路）：

```
ai_memory.jsonl（机器每日自动追加一行：判级+净流动性+ESI+异动）
      ↓ 每天生成
ai_daily.md = 使用指令 + 今日vs昨日判级diff + 异动榜 + 完整状态 + 最近7天记忆
      ↓ 人整段粘给任意 LLM
AI 输出：今日重点 / 判级合理性 / ≤3句白话结论 / 下周该盯什么
```

为什么不用向量数据库：向量检索适合"从海量文档里捞相关片段"，而这里是**固定结构的时间序列状态**——直接全量给（每天几千 token，成本可忽略），检索反而引入噪音且丢掉时间连续性。等 ai_memory 积累 4 周以上，"假设卡片对答案"就有原料了：判级历史 vs 实际走势，算出每条链的胜率，w 权重校准自然就有了。

## 四、已知的边界与降级

- Clash 没开：Polymarket/Yahoo/日元趋势降级为"缺"，FRED/统计局/人行/HL 不受影响。

## 附：一天多跑怎么跑（2026-09-15 v3）

| 命令（终端里） | 跑什么 | 出不出文章 | 动不动 git | 耗 LLM token |
|---|---|---|---|---|
| `.\vv.bat` | **全量 9 步**（= 直接调 `世界观采集.bat`，含自检+归档+发布） | 出（重写） | commit+push | 有（1次） |
| `.\vvs.bat` | **6 步轻跑**：world_feed → social_feed → whale_link → macro_insight → report → **verify** | **不出，旧文章原样保留** | **不碰 git** | **零** |
| `python llm_commentary.py` | 只重写文章 | 出 | 不动 | 有 |

- 终端用法：PowerShell 里 `.\vv.bat` / `.\vvs.bat`；cmd 里直接敲 `vv` / `vvs`；git bash 里 `./vv.bat`；双击也行。
- `./` 和 `.\` 是同一个意思（"当前目录下的这个文件"），只是 shell 习惯不同：PowerShell 要写 `.\`，cmd 可以省略，git bash 用 `./`。
- 推荐节奏：早上一次 `.\vv.bat`（出当天文章），盘中变化大就跑几次 `.\vvs.bat` 只补数据。
- 同日多跑为什么安全：快照追加、同 key 取最新、ai_memory.jsonl 同日重跑先删旧行、**daily.csv 主键 (数据日,key) 读-改-写不堆行**——数据不会脏、AI 记忆不会重复。
- 数据报告每次轻跑都会刷新（免费），LLM 文章只有 vv / 单跑 llm_commentary 才重写。
- **轻跑也会自检**（[6/6] 步），但**不叫 CLI、不碰 git**——盘中一天跑 N 次也不花钱、不产生提交。
- **A线鲸鱼段**：采集链里的 `whale_link.py` 会自动从云端拉知情钱快照（多 $71.18M/空 $3.81M 这类），变动规则：新建仓/平仓 ≥$50万、增减 ≥$50万且 ±20%、方向翻转必报。断网只跳过不报错。晨报 0.9 节引用。
